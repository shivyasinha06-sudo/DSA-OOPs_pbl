IntelliPlag

DSA & OOP Based Plagiarism Detection System

IntelliPlag analyzes submitted text against a large reference corpus using data structures, string matching and similarity analysis — built to demonstrate how theoretical DSA & OOP concepts translate into a practical software system.

C++ DSA OOP Trie Hashing N-Gram String Matching SQLite Flask API

Detect overlapping content using a combination of classical data structures and text-matching techniques. IntelliPlag preprocesses submitted text, compares it against documents stored in the SQLite corpus, uses n-grams and string matching to identify overlapping phrases, calculates similarity and containment measures, and ranks potentially matching source documents.

🧹

Text Preprocessing

Submitted text is lowercased, punctuation-stripped and tokenized before comparison — ensuring consistent matching regardless of formatting differences.

📚

SQLite Corpus

A 198 MB SQLite database stores reference articles. The engine loads up to 2 000 articles per query and builds an in-memory inverted index for fast lookup.

🔗

N-Gram Fingerprinting

Text is broken into overlapping 4-gram sequences. Each gram is hashed into a fingerprint and stored in a custom hash table for O(1) lookups.

📊

Similarity Analysis

Containment score measures how much of the input appears in a corpus document. Jaccard similarity provides a set-overlap measure between both documents.

How IntelliPlag Works

Six-stage pipeline from raw document to ranked results.

01 — INPUT

Document Submission

User submits a document through the web interface. The text is sent to the Flask API layer via a POST request.

02 — PREPROCESSING

Text Normalization

The C++ engine lowercases text, removes punctuation and tokenizes it into clean word sequences before any comparison.

03 — DATA STRUCTURES

Indexing

A custom HashTable, InvertedIndex and Vector<T> are used to process and index corpus documents in memory.

04 — N-GRAM GENERATION

Fingerprinting

Both input and corpus documents are split into overlapping 4-gram sequences. Each gram is hashed to a 64-bit fingerprint for fast comparison.

05 — MATCHING

String Matching & Similarity

A Trie indexes input phrases. KMP string matching locates exact phrase positions. Containment and Jaccard metrics quantify overlap.

06 — RESULTS

Ranked Output

A MaxHeap ranks matching documents by containment score. The top five matches are returned as structured JSON to the frontend.

Technology Stack

Every component in the current, working system.

⚙️

C++ Engine

Core plagiarism algorithm. All DSA structures and similarity calculations are implemented in standard C++.

🌲

Data Structures

Trie, Hash Table, Inverted Index, Vector<T>, Max-Heap — all hand-coded, no STL containers for core logic.

🗄

SQLite

198 MB reference corpus with ~246 000 articles. Accessed via the SQLite C amalgamation compiled alongside the engine.

🐍

Python / Flask

Minimal API layer. Accepts POST requests, writes text to a temp file, spawns the C++ engine safely via subprocess.run, parses JSON output.

🌐

HTML / CSS / JS

Single-file frontend served by Flask. Zero external frameworks — only Google Fonts and vanilla JavaScript.

🔁

GitHub Actions

CI pipeline compiles the C++ engine on Linux, installs Flask, and runs an integration smoke-test on every push.
